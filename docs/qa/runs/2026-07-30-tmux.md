## Usability defects

### P0/P1 release blockers

1. **Pane model is cosmetic.** Tab changes reducer state, but no pane focus is rendered and panes have no pane-specific actions.
2. **Annotation list is not navigable.** There is no selected annotation, source location, next/previous annotation, or reliable choice for edit/delete.
3. **Delete is immediate and ambiguous.** `d` deletes the first annotation matching the document without confirmation. A mnemonic sequence such as `]d` can unexpectedly become “move document, then delete.”
4. **Editing is unsafe/confusing.** The single-line field offers no documented replacement flow; Ctrl-A did not select existing text and produced a concatenated body.
5. **Live responsive layout is broken.** Crossing to 64 columns did not activate narrow layout; the status line became unusable.
6. **Staleness is invisible where the user looks.** The pre-TUI warning disappears behind alternate-screen entry, while status still says `Ready`.
7. **Diff context is insufficient.** Hunk headers are omitted, so users cannot understand function/section boundaries or distinguish hunks.
8. **Finish/destructive transitions lack confirmation.** Submission and cancellation semantics are not explained.

### P1/P2 discoverability and hierarchy

9. Markdown “Outline” does not list headings or navigate to them.
10. The initial screen exposes only `? help`; primary actions and current selection state are not discoverable.
11. Selection is represented primarily by color and has no textual anchor/range indicator.
12. All annotations are flattened into one clipped line without intent, location, selection, or wrapping hierarchy.
13. Wide layouts devote a large fixed panel to a one-item document list; narrow screens truncate status and annotation text.

## What worked reliably

- Runtime target validation and persisted stable coordinates.
- Old/new diff-side targeting for changed lines.
- Atomic autosave, result files, sessions, resume, and exports.
- Git tracked/untracked/binary acquisition.
- Piped stdin using the controlling terminal.
- Source read-only behavior and terminal cleanup in exercised paths.

## Recommendation

Do not add integrations or AI overlays yet. Replace the current shell interaction model first:

1. Introduce explicit modes and visible focus: files/content/comments/composer.
2. Add a command bar with contextual shortcuts and a searchable help/command palette.
3. Make annotations first-class list items with location, intent, selected state, jump/edit/delete.
4. Add hunk/header rows and file status/stat information to diff rendering.
5. Put stale state inside the persistent status/header area.
6. Make resize state reactive and design narrow layout independently.
7. Separate save, finish, and cancel, with confirmation where consequences are ambiguous.
8. Add PTY/tmux regression scenarios for every defect above.
